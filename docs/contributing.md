# Contributing to sound_comp

Thank you for your interest in contributing to `sound_comp`! We're excited to see what you build.

## Code of Conduct

This project and everyone participating in it is governed by a Code of Conduct. By participating, you are expected to uphold this code. Please report unacceptable behavior. (A formal Code of Conduct will be added soon). For now, please be respectful and constructive in all interactions.

## How to Contribute

### Getting Started

The project is designed to run directly in a browser-based environment like Google AI Studio that supports ES Modules and import maps. No local installation or build process is required.

1.  Load the project files (`index.html`, `index.tsx`, etc.) into your environment.
2.  Ensure the environment provides the necessary `API_KEY` as an environment variable for the Gemini API features to work.
3.  The application should run directly.

### Making Changes

1.  **Create a branch:** Create a new branch for your feature or bug fix. Use a descriptive name, like `feature/add-delay-effect` or `bugfix/fix-recording-glitch`.
2.  **Write clean code:**
    - Follow the existing code style.
    - Use TypeScript for type safety.
    - Write clear, understandable component logic.
    - Add comments for complex sections of code.
3.  **Commit your changes:** Write clear and concise commit messages. A good commit message explains the "what" and the "why" of the change.
4.  **Submit a Pull Request:** Push your branch and open a Pull Request against the `main` branch. Provide a clear description of the changes you've made.

### Reporting Bugs

If you find a bug, please create an issue in the project repository. Include the following information:

- A clear and descriptive title.
- Steps to reproduce the bug.
- What you expected to happen.
- What actually happened.
- Browser and Operating System information.

### Suggesting Enhancements

We'd love to hear your ideas for new features! Please create an issue to suggest an enhancement.

- Explain your idea clearly.
- Describe the use case and why it would be a valuable addition to `sound_comp`.
- If possible, include mockups or examples of how it might work.

Thank you for helping make `sound_comp` better!
